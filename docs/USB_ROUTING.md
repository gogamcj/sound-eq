# USB 오디오 라우팅 안내

## 원칙

* LAN(OSC)은 **제어 전용**입니다. 오디오는 **USB**로만 받습니다.
* USB 채널 번호와 믹서 채널 번호는 **서로 다른 개념**입니다. 믹서의 USB 출력 라우팅이 "USB n번으로 무엇을 보낼지"를 정합니다. 프로그램은 이를 자동으로 알 수 없으므로 사용자가 매핑을 입력합니다.

## 1. Windows 쪽 확인

1. Behringer WING USB 드라이버(ASIO)를 설치합니다. 드라이버 제어판에서 샘플레이트가 믹서와 같은지(보통 48 kHz) 확인합니다.
2. `python -m tools.verify_connection --audio`를 실행해 다음을 확인합니다.
   * 'WING 후보' 장치가 보이는지 (ASIO 장치를 우선으로 정렬합니다)
   * 지원 샘플레이트
   * 실제로 열 수 있는 최대 채널 수 (드라이버가 보고하는 값과 다를 수 있습니다)
3. `--audio-test 5`로 5초 동안 받으면서 신호가 있는 USB 채널 목록을 봅니다. 연주자에게 채널을 하나씩 소리 내 달라고 하면 매핑을 확인할 수 있습니다.

> 미검증: WING COMPACT USB 장치의 정확한 Windows 이름, 호스트 API(ASIO/WASAPI), WASAPI 경로의 채널 제한은 실제 장비에서 확인해 [HARDWARE_VERIFICATION.md](HARDWARE_VERIFICATION.md)에 기록해야 합니다.

## 2. 믹서 쪽 라우팅

WING의 라우팅 화면(ROUTING)에서 USB 출력 그룹(USB 1–48)에 소스를 지정합니다. 메뉴 이름과 위치는 펌웨어마다 다를 수 있으니 실제 장비 화면을 기준으로 하십시오. 일반적으로 다음 두 방식이 있습니다.

| 방식 | USB로 가는 신호 | 프로그램 설정 '신호 탭 위치' |
|---|---|---|
| A. 입력 소스를 그대로 USB로 (Local In, AES50 등) | 채널 EQ **이전** 신호 | `EQ 이전 신호 (pre_eq)` (기본값) |
| B. 채널 처리 뒤의 신호를 USB로 (펌웨어가 지원하는 경우, 탭이 EQ 뒤) | 채널 EQ **이후** 신호 | `EQ 이후 신호 (post_eq)` |

* **pre_eq**: 프로그램은 측정한 스펙트럼에 현재 믹서 EQ 커브(근사)를 더해 "지금 EQ를 거친 소리"를 추정하고 판단합니다. 적용한 뒤의 개선 확인도 근사 커브로 합니다. 측정이 아닌 예측이라는 뜻입니다.
* **post_eq**: 적용한 뒤 실제로 바뀐 소리를 다시 측정합니다. 자동 보정의 "적용 후 재분석"은 이 방식이어야 실측이 됩니다.

탭 위치를 잘못 설정하면 EQ 효과를 두 번 세거나 놓칩니다. 라우팅을 바꾸면 설정도 함께 바꾸십시오.

## 3. 매핑 입력

메인 화면에서 행(USB 입력)을 선택하고, '채널 설정'의 '믹서 채널'에 WING 채널 번호(`/ch/N`)를 넣습니다.

* 같은 믹서 채널을 두 USB 입력에 매핑하거나, 범위 밖 번호를 넣으면 경고합니다 (`ChannelMap.validate`).
* '매핑 안 함'인 채널은 분석만 하고 믹서 제어 대상에서는 빠집니다.
* 매핑은 공연 프로필(SQLite)에 저장됩니다. 믹서의 SHOW/SNAP/SNIP과는 별개입니다.
