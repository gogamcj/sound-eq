# 문제 해결

| 증상 | 확인할 것 |
|---|---|
| 'OSC 응답 (/?)' FAIL | IP 오타, 같은 서브넷인지, 케이블, Windows 방화벽의 UDP 허용, 포트 2223. 다른 프로그램이 WING을 독점하고 있지 않은지 |
| 디스커버리 응답 없음 | 브로드캐스트가 막힌 네트워크일 수 있음. IP를 직접 입력 |
| "장비 범위를 모른다 … 쓰기를 거부" | 이 펌웨어가 leaf 주소의 `,s ?`에 응답하지 않거나 형식이 다름. `reports/verify_*.json`의 `ranges`를 보고 형식을 알려 주시면 파서를 추가하겠습니다. 임시로 '보수적 기본 범위 사용'을 켤 수 있지만, 공식 값이 아님 |
| EQ 읽기에서 '응답 없음: [...]' | 해당 경로가 이 펌웨어에 없을 수 있음 (EQ 모델이 STD가 아니거나 경로 형식이 다름). 그 키는 사용하지 않음 |
| '적용 실패 (재조회 값 불일치)' | 장비가 값을 다르게 양자화했거나 단위를 다르게 해석함. 이력의 요청값과 실제값을 비교 |
| '현재값이 예상과 달라 중단' | 추천을 계산한 뒤 콘솔에서 값이 바뀜. 'EQ 다시 읽기' 후 다시 추천 |
| 오디오 장치가 보이지 않음 | WING USB 드라이버 설치, USB 케이블, 다른 DAW가 ASIO를 독점하고 있지 않은지. 오디오 라이브러리 로드 실패 메시지를 확인 |
| ASIO 장치가 목록에 없음 | sounddevice가 ASIO 지원 DLL을 로드하지 못한 경우. 환경변수 `SD_ENABLE_ASIO=1`이 설정됐는지(프로그램이 자동 설정), sounddevice 버전 확인 |
| 채널 수가 적게 열림 | WASAPI/MME 경로는 채널이 제한될 수 있음 → ASIO 장치 선택 |
| '드롭'이 증가 | 분석이 밀림. FFT 크기를 줄이거나 홉을 늘리고, 수신 채널 수를 실제 사용 수로 줄임. 노트북 전원 모드를 '최고 성능'으로 |
| '오류'(PortAudio 상태) 증가 | USB 버퍼 오버플로. 드라이버 버퍼 크기를 늘리고, USB 허브 대신 직결 |
| 모든 채널이 '무음' | USB 라우팅에 소스가 지정되지 않음 ([USB_ROUTING.md](USB_ROUTING.md)) |
| 매핑이 맞지 않음 | `--audio-test`로 실제 신호가 오는 USB 채널을 확인하고 채널 설정을 수정 |
| 추천이 계속 '데이터 부족' | 유효 신호가 8초 이상 필요함 (-45 dBFS 이상). 신호가 작으면 기준을 조정 |
| 자동 보정이 바로 꺼짐 | 상단에 표시된 중지 사유를 확인 (LAN 단절, 오디오 오류, 사용자 정지). 채널별 정지 사유는 '추천/상태' 열 |

로그 파일은 `logs\wing_auto_eq.log`(순환 5 MB × 5)에 있고, 이벤트와 이력은 `data\wing_auto_eq.db`(SQLite)에 저장됩니다.
